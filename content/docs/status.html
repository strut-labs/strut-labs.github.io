Implementation status

The documentation describes the implemented language contract unless a page explicitly marks something as deferred. This page is the quick implementation snapshot.

Strut 0.0.1 implementation

  • Portable C++20/CMake bootstrap with Linux, macOS, and Windows treated as first-class targets.
  • Lexer, parser, semantic analysis, typed source-mapped IR, and native executable generation behind a backend boundary.
  • Primitive/fixed-width types and aliases, strings, dynamic/fixed arrays, explicit collection modules (vector, deque, list, hash/ordered maps and sets, queue/stack/priority queue), heterogeneous tuples including one-tuples, JSONIC-backed json, structs, enums, generics, nullability, switch, and exhaustive enum match.
  • First-class functions, named/generic functions, closures, inferred and explicitly typed generic lambdas, async functions/lambdas, and futures.
  • Fixed-precedence operator overloading, lambda operator definitions, dereference overloads, and custom =/:= semantics.
  • No-GC memory model with reference-counted T*, non-owning T&, weak_ptr<T>, and explicit unsafe/ptr<T>, including raw->member.
  • Checked error signatures, throw, typed try/catch, and catch-all handling.
  • Filesystem APIs with scalar/vector/wildcard copy/move/removal, recursive traversal, metadata/path helpers and optimized whole-file text/binary I/O; streams, in/out/err; environment access, clocks/sleeping, argv-safe exec, child processes/pipes, and explicit shell execution.
  • Native threads, mutexes/scoped locking, typed channels, a shared multithreaded async executor, and documented cross-thread safety policy.
  • C ABI FFI, static/dynamic native libraries, and static, dynamic, or mixed final linking with release dead-code elimination/stripping where supported.
  • strut.json package manifests, lock/cache handling, local package workflows, explicit angle-bracket standard modules, and include <package> resolution; quoted includes remain local/native dependencies.
  • Cross-platform TCP networking, verified client TLS through libcurl, direct HTTPS serving through OpenSSL, concurrent HTTP routing, bounded graceful shutdown, request limits, JSON requests/responses, and system SQLite integration.
  • Compile-time file/directory embedding and static-asset serving for one-binary applications.
  • strut init, persistent .o/.obj files, per-object .info.json dependencies, Nift-style modified-time invalidation, and strut make.
  • strut test test discovery/filtering and strut fmt/--check canonical formatting.
  • Built-in strut lsp language server with diagnostics, definition, completion, hover, and formatting, plus syntax-highlighted CLI error snippets and standard-library completions.
  • Named cross-compilation targets and target-partitioned build caches.
  • Frontend fuzzing, sanitizer-backed memory stress, concurrency stress, FFI hardening, and multi-program/package dogfooding.

Project build state

.strut/config.json is project configuration. Generated object files live in .strut/obj, generated bootstrap sources in .strut/gen, and dependency/build records in .strut/info. Unchanged objects are reused; changed dependencies rebuild only affected units.

Current benchmark baseline

The CP86 one-binary todo application established a development-host baseline for compile time, stripped executable size, startup, idle RSS, and localhost HTTP throughput. Those numbers are intentionally treated as profiling baselines rather than external performance claims until the dedicated benchmark phase begins.

Platform certification

The compiler and generated C++ are certified in GitHub Actions on Linux x64 with GCC and Clang, Linux ARM64 with GCC, macOS ARM64 with AppleClang, and Windows x64 with MSVC. The independent regression suite is also green across Ubuntu, macOS, and Windows.

Stability work

The language design, compatibility/versioning, security/reliability, and release-candidate audits are complete for 0.0.1. The current development baseline contains 139 independently isolated regressions plus compiler unit, fuzz, stress, generated-code, package, and backend dogfood coverage.

Still deferred

HTTP/2, WebSockets, ACME/certificate automation, reverse-proxy behavior, and a centralized package registry remain deliberately deferred.
