Implementation status

The docs distinguish the Strut language contract from compiler support. Planned syntax is useful for design review, but it must not be mistaken for a feature that already compiles.

Implemented through CP19

  • Portable C++20/CMake bootstrap project with Linux, macOS and Windows kept as architectural targets.
  • strut --help, --version, token dumping and parse/semantic --check workflow.
  • JSONIC-backed machine-readable compiler metadata.
  • Independent black-box regression harness.
  • .p/.h source loading, source spans, comments, identifiers, keywords, operators and primitive literals.
  • Declarations, assignment, mandatory semicolons, expression precedence, member/index syntax, compound assignment and increment/decrement parsing.
  • if/else, while, C-style for, and for (item : items).
  • Named functions, explicit return types, out-of-struct method definitions, [T] generic declarations, lambdas and function-value types.
  • Stable source-located diagnostics, lexical scopes, duplicate-definition checks and separate value/function/type namespaces.
  • int_*, uint_*, double_*, ordinary type aliases including int/uint/double, primitive type inference, compatibility checking and const enforcement.

Next

CP20 introduces the typed IR and a documented backend contract. Later language pages describe the current design contract and remain planned until their implementation checkpoints are completed.
