Implementation status

The docs distinguish the Strut language contract from compiler support. Planned syntax is useful for design review, but it must not be mistaken for a feature that already compiles.

Implemented through CP49

  • Portable C++17/CMake bootstrap with GCC and Clang warnings-as-errors certification; Linux, macOS and Windows remain first-class architectural targets.
  • Lexer, parser, semantic analysis, typed source-mapped IR and native executable generation through a backend boundary.
  • strut file.p, deterministic output naming, -o, --check and token dumping.
  • Primitive width types and aliases, := inference, explicit typing, const, arrays, maps, strings, JSONIC-backed json and structs.
  • First-class named functions, lambdas/closures, higher-order collection helpers, generic functions and generic structs.
  • No-GC memory model prototype with reference-counted ptr<T>, ref<T>, weak_ptr<T>, unsafe and raw_ptr<T>; sanitizer builds are supported.
  • Semantic local includes, package-include syntax, abstract struct contracts and one concrete/data-bearing base plus multiple contract bases.
  • Integer-backed enums with explicit values, non-fallthrough switch, exhaustive enum match, checked error signatures and checked throw propagation.
  • Independent black-box regression suite exercises compiler failures and generated native programs.
