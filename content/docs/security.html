Security model

Strut separates the safe language surface from explicit unsafe/native boundaries. The goal is deterministic native programs without a tracing garbage collector while preventing lifetime errors promised by the safe type system.

Safe memory

T* owns through reference counting, T& is a compiler-checked non-owning/non-null borrow, and weak_ptr<T> provides non-owning access to shared ownership. Safe null dereferences are checked rather than becoming native undefined behaviour.

Unsafe and FFI

ptr<T> operations and C ABI calls require an explicit unsafe boundary. Strut cannot prove the behaviour of external native code; unsafe regions should remain small and be wrapped by safe APIs.

Processes and packages

exec is argv-based by default rather than silently invoking a shell. Package paths are validated against escaping package roots, and lock metadata is intended to make dependency selection reproducible.

TLS

HTTP client TLS uses libcurl with certificate and hostname verification enabled by default. HTTPS servers use OpenSSL with TLS 1.2 or newer, validate the certificate/private-key pair before binding, and never fall back silently to plaintext. Plain HTTP does not pull the OpenSSL runtime component.

Hardening

The project includes frontend fuzz smoke tests, sanitizer-backed memory/runtime stress, concurrency stress, FFI ABI fixtures, and cross-platform CI workflows. Platform release certification remains separate from implementing the feature.
