HTTP client

The official HTTP client uses libcurl, keeps TLS certificate and hostname verification enabled, follows redirects by default, and integrates with Strut's JSON and async facilities.

The current HTTP client API is selected automatically when these functions are used; do not add include <http>;. Native compilation requires the libcurl development package.

GET request

function main() -> int : HttpError {
    response := http_get("https://example.com/api/status");
    print(response.status);
    print(response.body);
    return 0;
}

JSON response

function main() -> int : HttpError {
    body := http_get_json("https://example.com/api/user");
    print(body["name"]);
    return 0;
}

Custom requests

http_request accepts a method, URL, and JSON options object for headers, request bodies, timeouts, and redirect policy.

options := {
    "headers": {"Authorization": "Bearer token"},
    "body": {"name": "Nick"},
    "timeout_ms": 5000,
    "follow_redirects": true
};
response := http_request("POST", "https://example.com/api/users", options);

Async requests

pending := http_get_async("https://example.com/api/status");
response := await pending;

Streaming policy

HTTP responses are currently buffered. A public streaming response API is deliberately deferred rather than exposing libcurl callbacks as language API prematurely.

Verified HTTPS client with a private CA

http_get_ca(url, ca_file) trusts an explicit PEM CA bundle while retaining certificate and hostname verification. There is no insecure convenience mode.

HTTP server

Strut's server API is built on the cross-platform TCP substrate. Routes support path parameters, query values, headers, request bodies, JSON parsing, and synchronous or async handlers.

function main() -> int : NetworkError {
    http_server app := http_server();

    app.get("/hello/:name", (http_request req) => {
        name := req.params["name"];
        return http_text("hello " + name);
    });

    app.listen("127.0.0.1", 8080);
    return 0;
}

SQLite-backed route

function main() -> int : (NetworkError, SqliteError) {
    db := sqlite_open(":memory:");
    db.exec("CREATE TABLE notes(id INTEGER PRIMARY KEY, text TEXT)");

    app := http_server();
    app.get("/notes", (http_request req) => {
        return http_json_response(db.query("SELECT * FROM notes"));
    });
    app.listen("127.0.0.1", 8080);
    return 0;
}

Lifecycle and operational limits

The server accepts requests concurrently. stop() closes the listener and drains active handlers up to the configured shutdown timeout; it is safe before start and idempotent. running() reports whether the server is accepting or draining.

app.timeouts(30000, 30000, 5000, 5000);
app.limits(1048576, 65536, 100, 1024);

listener := thread(() => { app.listen("127.0.0.1", 8080); });
wait_for_shutdown_signal();
app.stop();
listener.join();

The timeout values are read, write, idle, and graceful-shutdown milliseconds. Limits cover request-body bytes, header bytes, header count, and active connections. Malformed or oversized requests receive controlled HTTP responses.

HTTPS server

listen_tls loads a PEM certificate chain and matching private key before opening the listener. Missing, invalid, unreadable, or mismatched material produces TlsError; Strut never falls back to plaintext. OpenSSL is linked only when this API is used.

function main(string command, string[] args) -> int : (NetworkError, TlsError) {
    app := http_server();
    app.get("/health", (http_request request) => { return http_text("secure"); });
    app.listen_tls("127.0.0.1", 8443, args[0], args[1]);
    return 0;
}

Async handlers

Use get_async or post_async when a handler performs async work. The server awaits the returned Strut future before writing the response.

app.get_async("/api/items", async (http_request req) => {
    data := await load_items();
    return http_json_response(data);
});

Request data

http_request exposes method, path, headers, query, params, and body. req.json() parses the request body with JSONIC.
