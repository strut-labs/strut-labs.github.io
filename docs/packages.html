Packages

Strut aims for a deliberately small standard library and a curated package ecosystem. Package includes use angle brackets; local project headers use quotes.

Package include

include <http>;
include <sqlite>;

Local include

include "auth.h";
include "models/user.h";

Package direction

Official packages are intended to live under a dedicated Strut packages organisation. HTTP, SQLite, PostgreSQL, TLS, and WebSocket support are examples of functionality that can evolve independently from the language runtime.

Core facilities that directly define the language experience—such as strings, collections, JSON, basic IO, process execution, and concurrency primitives—remain available without turning every small program into a dependency-management exercise.

Project manifest

Strut projects and packages use a JSON strut.json manifest. JSONIC is used by the bootstrap compiler to parse and validate the format.

{
  "name": "todo-service",
  "version": "0.1.0",
  "entry": "src/main.p",
  "dependencies": {
    "http": "^0.2.0",
    "sqlite": "~0.3.1"
  }
}

Version requirements

Initial requirements deliberately stay small: exact 1.2.3, compatible ^1.2.3, patch-compatible ~1.2.3, and *. Floating labels such as latest are not part of the reproducible package contract.

Lockfile

strut.lock.json records exact versions, immutable source revisions, content checksums, and transitive dependency edges. Normal builds consume the lock without silently upgrading dependencies.

Shared cache

Packages are cached once per user rather than copied into every project. STRUT_HOME can override the base location; otherwise Strut follows the platform cache convention on Linux, macOS, and Windows.

Package CLI

The current package CLI supports deterministic local/cache workflows. Strut now has an HTTP client, but remote package fetching is intentionally still separate from the package resolver until its registry/security contract is designed.

strut add ../http
strut list
strut install
strut remove http

include <name> resolves the package entry declared by the cached version selected from the project manifest. include <name/path.h> resolves an explicit package file.
