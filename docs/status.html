Implementation status

The docs distinguish the Strut language contract from compiler support. Planned syntax is useful for design review, but it must not be mistaken for a feature that already compiles.

Implemented through CP29

  • Portable C++20/CMake bootstrap with GCC and Clang warnings-as-errors certification; Linux, macOS and Windows remain first-class architectural targets.
  • Lexer, parser, semantic analysis, typed source-mapped IR, and a backend boundary separated from syntax.
  • Native executable generation via the C++20 backend, including calls, returns, arithmetic, control flow and print(...).
  • strut file.p compilation, deterministic output naming, -o, plus --check and token-dump workflows.
  • Primitive width types and aliases, := inference, explicit typing, widening checks and const.
  • Dynamic T[] and fixed T[n] arrays with bounds-safe indexing and iteration.
  • Owned strings, core string helpers, split/join, and numeric conversion paths using std::from_chars.
  • map<K,V> with keyed [key: value] literals, deterministic ordered iteration and core lookup/mutation operations.
  • Built-in json backed by JSONIC: object/array values, navigation, structural equality, parse, stringify, pretty output and encode groundwork.
  • Struct fields, Type { field: value } construction, inline methods and Type::method definitions.
  • Independent black-box regression suite covering compiler failures and generated native programs.
