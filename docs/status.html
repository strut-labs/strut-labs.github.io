Implementation status

The docs distinguish the Strut language contract from compiler support. Planned syntax is useful for design review, but it must not be mistaken for a feature that already compiles.

Implemented through CP39

  • Portable C++17/CMake bootstrap with GCC and Clang warnings-as-errors certification; Linux, macOS and Windows remain first-class architectural targets.
  • Lexer, parser, semantic analysis, typed source-mapped IR and native executable generation through a backend boundary.
  • strut file.p, deterministic output naming, -o, --check and token dumping.
  • Primitive width types and aliases, := inference, explicit typing, const, arrays, maps, strings, JSONIC-backed json and structs.
  • Nullable T?, ?., ?? and flow narrowing after null checks.
  • First-class named functions, typed function values, generic lambdas and escaping closures with value captures.
  • Higher-order collection helpers including map/filter/reduce/find/count/sort plus count_by, index_by and partition.
  • No-GC memory prototype: reference-counted ptr<T>, independent referent/binding constness, non-owning ref<T>, weak_ptr<T> and cycle warnings.
  • unsafe and unmanaged raw_ptr<T>, with raw dereference/arithmetic prohibited outside unsafe blocks.
  • Independent black-box regression suite exercises compiler failures and generated native programs.

Next

CP40 is the first dedicated memory-safety certification pass: hostile lifetime cases, weak upgrades, double-destruction attempts, iterator invalidation and sanitizer/Valgrind checks.
